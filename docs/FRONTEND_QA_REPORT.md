## Verified screen

The initial Next.js App Router screen reads the stored Beed CHIRPS observations through FastAPI. It does not contain a fallback observation array. API failure produces an inline error stating that demonstration data was not substituted.

Design direction: `data-terminal`, seed `20261101`, generated by the required `design-taste-frontend` skill. Public Sans is used for interface text and JetBrains Mono only for changing figures, dates and units. The rainfall blue is limited to the data line and 1 px selection marks.

Live thing: The rainfall series, accumulation, coverage, freshness and acquisition rows all change from the FastAPI/PostGIS response.

Caps applied: None applicable to this app screen. The photography and marketing-primary-action caps do not apply to a scientific monitoring screen under the skill's app-screen rules.

Top three problems (most visible first), each with the screenshot it shows in and the fix:

1. The first dev capture showed a blank chart because `127.0.0.1` was not an allowed Next.js development origin (`frontend-qa-live/desktop-fold.jpg`). Fixed with documented `allowedDevOrigins`; the production SVG is visible at all widths.
2. The initial phone bottom bar used icons without labels and the first added label sat 11 px from the edge (`frontend-qa-production/mobile-fold.jpg`). Fixed with short 11 px labels and `Monitor` at a safe inset.
3. The first header had a product-name eyebrow above the noun title (`frontend-qa-final/desktop-fold.jpg`). Removed; the screen now opens directly with the district question.
